Active Directory SOC lab: monitoring, attack simulation and Sysmon

Windows Server 2019, Windows 10, Kali Linux, VMware, Group Policy, Windows Event Forwarding, Sysmon, Wazuh, Nmap

An academic assessment (Boston Institute of Analytics, November 2025) of a three-machine lab. The goal was to check that a small Active Directory domain records and centralises the events a SOC would need.

What I built

  • A domain controller (Windows Server 2019) for the LABtes.local domain, a domain-joined Windows 10 client and a Kali Linux attacker machine.
  • Group Policy audit settings for logon success and failure, checked with gpupdate /force and auditpol.
  • Windows Event Forwarding, so the domain controller collects security events from the client.

What I tested

  • Scanned the client from Kali with Nmap and found SMB (445) and RPC (135) open.
  • Simulated repeated failed logins over SMB with smbclient, then confirmed Event ID 4625 (logon failure) appeared in the Security log with the attacker’s IP address.
  • Installed Sysmon and confirmed Event ID 1 (process create) for ping.exe and Event ID 11 (file create).
  • Registered both Windows machines as agents in the Wazuh dashboard and confirmed the Wazuh service was running. Wiring Sysmon and Security logs into Wazuh alerts is the next step.

Findings

FindingImpactRecommendation
Audit logging incompleteMediumExtend Advanced Audit Policy to object access and privilege use.
Weak password policyMediumApply CIS-level password and lockout rules.
Remote management ports openMediumLimit RPC and RDP to admin IP ranges and monitor them.
SMB exposed internallyLowRestrict port 445 to trusted hosts and log failed access.
Single log collectorLowForward to a SIEM so logs stay available.

Next steps I identified: a full SIEM deployment, Sysmon on every machine, and Active Directory posture checks with Purple Knight or BloodHound.

ISO 27001:2022 Statement of Applicability project

ISO/IEC 27001:2022, Annex A controls

A Statement of Applicability (SoA) is the document an organisation uses to list the Annex A controls of ISO 27001, say whether each one applies and explain why. The 2022 edition groups 93 controls into four themes: organizational, people, physical and technological.

What I did

  • Went through the ISO 27001:2022 Annex A controls and learned how the four themes fit together.
  • Worked on control applicability: deciding whether a control applies and writing the justification for that decision.
  • Documented the security risks behind those decisions.
  • Listed the evidence an auditor would expect to see for each control, such as policies, logs and records.
  • Wrote remediation recommendations for the gaps I found.

How it connects to SOC work

Several Annex A controls cover the same ground as my Active Directory lab: logging (8.15), monitoring activities (8.16) and information security incident management (5.24 to 5.28). Working on the compliance side showed me why a SOC keeps logs and records incidents: it needs to prove, not just say, that controls work.
